# IoT 平台 CA 证书与 TLS 单向认证知识文档

整理日期：2026-11-03

适用场景：设备通过 MQTT over TLS 或 HTTPS 接入自建 IoT 平台，平台使用华为云 ELB，设备验证服务端身份，随后进行加密通信。

本文说明通用 PKI/TLS 原理和工程流程。华为云 ELB 的 TLS 卸载能力、证书产品、自动续签与自动部署支持范围，需要按实际区域、实例类型、监听器及订单确认；本文不将 AWS 的配置能力套用于华为云。

## 1. 核心结论

- 向公共 CA 申请的是属于接入域名的服务器证书，不是为设备申请一张新的公共根 CA 证书。
- TLS 在 ELB 终止时，ELB 部署服务器证书、对应私钥和匹配的中间 CA 证书链。
- 设备预置可信根 CA 证书或信任库，并验证服务器证书链、域名、有效期和用途。
- 单向认证不要求设备提供客户端证书，但平台仍应在加密连接内认证设备并控制权限。
- 中间证书链由多张独立证书组成，完整 TLS 握手时通常由服务端直接提供。
- 服务器证书续期是签发并部署新证书，不能修改旧证书的有效期。
- 服务器证书续期通常不需要更新设备根证书，前提是新链仍可验证到设备接受的信任锚。
- 长期运行设备必须规划根信任迁移。备用 HTTP 可以传输更新包，但更新必须经过独立数字签名验证。

## 2. 术语与文件

| 名称 | 含义 | 是否需要保密 |
| --- | --- | --- |
| CA | 证书颁发机构，负责按规则签发证书 | CA 的签发私钥需要保密 |
| 根 CA 证书 | 通常为自签证书，承载根 CA 身份和公钥，可被配置为信任锚 | 否，但必须可信获取并防止未经授权替换 |
| 中间 CA 证书 | 包含中间 CA 公钥和签发约束，由上级 CA 签署 | 否 |
| 服务器证书 | 包含服务器公钥、域名、有效期、用途及签发者签名的叶子证书 | 否 |
| 服务器私钥 | 与服务器证书公钥对应，用于 TLS 握手中的身份证明 | 是 |
| CSR | Certificate Signing Request，证书签名请求 | 通常不需要保密，不包含私钥 |
| SAN | Subject Alternative Name，服务器证书中的域名或 IP 身份信息 | 否 |
| 信任锚 | 通过可信流程预先配置的 CA 身份、公钥及相关策略 | 不需要保密，但必须保护完整性 |
| PEM / DER | 证书等材料的编码格式；PEM 使用文本封装，DER 使用二进制编码 | 取决于承载的是证书还是私钥 |

示例文件：

```text
server.key          服务器私钥
server.csr          提交给 CA 的申请材料
server.crt          CA 签发的服务器证书
intermediates.pem   匹配的中间 CA 证书集合
root-ca.pem         设备信任的根 CA 证书
```

文件扩展名不能决定文件内容，应检查实际编码和对象类型。

## 3. 根、中间 CA 与服务器证书的关系

以下箭头表示“上级使用自己的签发私钥签署下级证书”：

```text
根 CA 证书：包含根 CA 公钥，设备预置信任
    |
    v
中间 CA A 证书：包含 A 的公钥，由根 CA 签署
    |
    v
中间 CA B 证书：包含 B 的公钥，由 A 签署
    |
    v
服务器证书：包含服务器公钥与 mqtt.example.com，由 B 签署
```

实际可以只有一级中间 CA，也可以有多级。同一个中间 CA 可以签发很多服务器证书。

设备用 B 的公钥验证服务器证书签名，用 A 的公钥验证 B，再用本地可信根的公钥验证 A。验证还包括域名、有效期、用途、CA 约束和算法等检查，不能仅验证签名。

### 3.1 中间链是多张证书，不是一张包含所有公钥的证书

一个 PEM 文件可以连续装入多张独立证书。下面内容是结构示意，不是真实可解析的证书：

```text
-----BEGIN CERTIFICATE-----
中间 CA B 的证书编码
-----END CERTIFICATE-----
-----BEGIN CERTIFICATE-----
中间 CA A 的证书编码
-----END CERTIFICATE-----
```

每组 `BEGIN CERTIFICATE` 到 `END CERTIFICATE` 对应一张独立证书。ELB 界面如果接受完整证书链，常见排列为服务器证书、直接签发中间 CA、再上一级中间 CA；如果有单独链字段，则该字段通常只填中间证书。必须按实际 ELB 格式要求配置。

### 3.2 根证书为什么可信

根证书不是因为“自签”就可信。设备信任它，是因为制造商通过出厂烧录、签名固件或其他可信流程将其设为信任锚。

服务端即使发送一张根证书，也不能因此让设备自动信任该根。公共 CA 的根证书一般在申请之前就已存在，不会因本次购买重新计算有效期。

## 4. 单向认证如何实现加密通信

单向认证表示设备验证服务端证书，服务端不要求设备提交客户端证书；“单向”不表示只有一个方向加密。

采用现代 ECDHE 密钥交换的完整握手，概念流程如下，省略 TLS 1.2、TLS 1.3 的报文差异及会话恢复：

```text
设备发送 TLS 能力、目标主机名 SNI 和密钥交换信息
    -> ELB 返回协议选择、服务器证书、中间链和密钥交换信息
    -> 服务端在握手中证明持有服务器私钥
    -> 设备验证证书链、域名、有效期、用途和相关约束
    -> 双方通过密钥交换结果派生会话密钥
    -> 双方确认握手
    -> 使用协商的对称加密算法保护上下行数据
```

证书和私钥负责身份认证；密钥交换和会话密钥负责数据加密与完整性保护。现代 TLS 不是用服务器证书逐条加密 MQTT 消息。CA 不参与设备的每次连接。

握手后，平台可通过每设备密钥、Token 或 MQTT 用户名密码识别设备，并限制发布、订阅权限。TLS 单向认证本身不证明设备合法。

## 5. 首次向公共 CA 申请服务器证书

### 5.1 准备域名

拥有并管理 `example.com`，选择 `mqtt.example.com` 作为接入地址，准备 DNS 管理权限。设备连接和证书域名验证均使用该业务域名，而不是临时 IP 或 ELB 厂商域名。

DNS 将业务域名指向 ELB 只解决寻址问题，TLS 仍必须验证业务域名身份。若确实按 IP 验证，需要服务器证书具有对应 IP SAN。

### 5.2 选择证书产品与签发链

| 类型 | 主要核验内容 | 对单向认证的意义 |
| --- | --- | --- |
| DV | 域名控制权 | 通常足够满足服务器域名认证 |
| OV | 域名控制权及组织身份 | 适合需要组织身份核验的场景 |
| EV | 更严格的组织身份核验 | 按业务要求选择 |

DV、OV、EV 主要区别在身份核验，不意味着更高验证等级天然提供更强通信加密。

同时确认密钥算法、证书链算法、ELB 与设备兼容性。RSA 2048 可作为兼容性测试起点；是否选 ECDSA，应结合实际设备能力判断。

### 5.3 生成私钥与 CSR

手动申请可使用 OpenSSL。证书管理平台若提供代生成能力，也可以由平台生成；此时必须了解私钥的保存和交付方式。

以下是支持 `-addext` 的 OpenSSL 环境下的示例，并未在实际平台执行：

```bash
openssl genpkey -algorithm RSA \
  -pkeyopt rsa_keygen_bits:2048 \
  -out server.key

chmod 600 server.key

openssl req -new \
  -key server.key \
  -out server.csr \
  -subj "/CN=mqtt.example.com" \
  -addext "subjectAltName=DNS:mqtt.example.com"
```

CSR 包含公钥和申请信息，不包含私钥。CSR 自身由申请者私钥签名，用于证明持有该私钥，但这不赋予公共可信身份，也不是一张自签服务器证书。

采用自行生成 CSR 的模式时，向 CA 提交 CSR，不提交服务器私钥。私钥不要放入源码仓库或设备固件。

### 5.4 提交申请并完成验证

通过华为云证书管理服务或直接向公共 CA 申请，提交 CSR 和域名资料。按订单要求完成 DNS TXT/CNAME、文件验证或其他支持的域名验证；OV、EV 还需要组织核验。

华为云是购买和管理入口，实际签发者由所选产品决定。不要将“在华为云购买”理解为设备一定信任某张华为云根证书。

### 5.5 领取并检查签发结果

获取服务器证书及匹配的中间链，从官方可信渠道取得候选根并核对指纹。检查服务器证书 SAN、有效期、服务器认证用途，以及公钥是否与服务器私钥对应。

CA 负责签发服务器证书，不会把自己的 CA 私钥交给申请人。

## 6. 在华为云 ELB 部署

### 6.1 先确认协议与 TLS 终止位置

- 原生 MQTT over TLS 常用端口为 `8883`，需要确认 ELB 是否支持适合原生 TCP 应用的 TLS 监听和卸载。
- HTTPS 常用端口为 `443`，使用 HTTPS 监听。
- MQTT over WSS 需要 HTTPS/WebSocket 支持以及对应 Broker 配置。
- HTTPS 监听不能直接替代原生 MQTT 的 TLS 监听。

TLS 在 ELB 终止时：

```text
设备 -- TLS --> ELB -- TCP --> MQTT Broker
                |
                +-- 服务器证书、私钥、中间链部署在这里
```

设备到 ELB 加密，ELB 到 Broker 的 TCP 段不加密。如果要求后端也加密，需要确认 ELB 的后端 TLS 能力及是否验证后端身份，并在 Broker 部署证书和私钥。

若使用 TCP 透传：

```text
设备 -- TLS 密文经过 ELB TCP 透传 --> MQTT Broker
                                      |
                                      +-- 在这里终止 TLS 并部署证书
```

此时证书轮换要更新 Broker，ELB 不参与该 TLS 握手。

### 6.2 TLS 卸载场景的部署步骤

1. 在证书管理服务中申请证书，或导入外部 CA 签发的服务器证书、私钥与匹配链。
2. 按 ELB 要求创建服务器证书对象，确认 PEM 格式、链顺序及私钥是否要求未加密。
3. 将服务器证书绑定到支持的 TLS/HTTPS 监听器，配置单向认证及兼容的安全策略。
4. 配置后端目标、健康检查和访问规则，明确后端是否加密。
5. 将业务域名通过支持的 DNS 记录指向 ELB。
6. 检查实际对外证书和真实设备连接，而不只检查证书对象是否创建成功。

设备尽可能发送 `SNI=mqtt.example.com`。如设备不支持 SNI，需要确认 ELB 默认服务器证书及无 SNI 行为。

单向认证下，设备不需要客户端证书。ELB 上用于验证客户端证书的“CA 证书”配置项，与设备本地验证服务器的根信任库用途不同，不能混淆。

## 7. 设备集成与证书缓存

### 7.1 设备配置

```text
接入域名：             mqtt.example.com
接入端口：             8883
可信 CA：              对应根 CA 或包含它的信任库
验证服务端证书：       开启
验证主机名：           开启，目标为 mqtt.example.com
SNI：                  mqtt.example.com
客户端证书和私钥：     单向认证不配置
```

Linux 设备可以使用包含对应根的系统信任库；MCU/RTOS 设备通常把根以 PEM 或 DER 放入固件或受保护存储，并交给成熟 TLS 库验证。

必须验证证书链、主机名、服务器和中间证书有效期、用途、CA 约束及算法。吊销检查的能力和策略应结合设备联网能力另行明确。

设备时间必须合理且防止任意回退。无 RTC 设备应设计出厂时间基线、受保护的时间持久化及校时流程，不能长期关闭有效期检查。

### 7.2 中间证书缓存不是必需的更新任务

完整握手中，ELB 通常直接发送服务器证书和中间链，设备不需要再访问 CA 网站获取。

设备可以使用 TLS 库提供的中间证书缓存，但常规 TLS 不会因设备已有缓存就自动让服务端省略证书链。缓存不能直接提升为可信根，也不能绕过验证。

减少流量和计算开销应优先考虑 MQTT 长连接及双方支持的 TLS 会话恢复。会话恢复行为取决于 TLS 版本、设备库和 ELB，不能保证每次成功。

## 8. 服务器证书续期与自动化

证书有效期是被签名内容，不能自行延长。到期前需要重新签发并部署新证书。

| 动作 | 含义 |
| --- | --- |
| 自动续费 | 支付费用或产生下一周期订单 |
| 自动续签 | 满足验证条件后签发新证书 |
| 自动部署 | 将新证书、匹配私钥与链部署到实际 TLS 终止点 |

完整自动化应覆盖：

```text
续签触发 -> 必要验证 -> 新证书签发 -> 部署 -> 监听器使用新证书 -> 对外验证
```

首次一键部署不等于续签后自动部署。购买前应确认所选华为云产品支持哪些动作，是否需要人工验证，是否支持当前 ELB 的持续更新。

续期时服务器证书必须换新，私钥可以按规则复用或轮换，但必须与新证书匹配；中间链以本次签发为准；设备根是否需要更新取决于新链是否仍被设备接受。

为实际入口配置到期告警，提前留出验证、审批、部署和回退时间。可采用到期前 60/30/14/7 天等分级提醒，但必须结合实际证书有效期及续签周期调整。

## 9. 长期设备的根信任生命周期

### 9.1 选择剩余生命周期较长的根

可以把“服务器链最终连接到剩余有效期超过 10 年的根”作为采购条件，但能否指定根取决于 CA、产品和申请入口。CSR 通常不能指定任意签发根。

需要获得根名称、SHA-256 指纹、到期时间、完整候选链，并确认产品支持使用该链。不能仅凭 CA 品牌，或单独下载一张较长有效期的根，就认为该根能验证本次证书。

按预计出厂和使用日期计算寿命，并为库存、交付、维修预留缓冲。还需确认未来续签是否支持通向该根的链及变更通知机制。

### 9.2 根到期与信任锚的区别

RFC 5280 将信任锚作为预先可信的验证输入，不同实现可能对承载信任锚的自签证书有效期采取不同规则。因此根到期不一定在所有设备上立即失败，必须测试实际 TLS 库。

不能依赖忽略根到期长期运行。CA 可能更换链、停用密钥，算法和信任策略也可能变化。

### 9.3 预置多个根并分阶段迁移

```text
阶段 1：设备信任 R1 和 R2，服务端使用通向 R1 的链
阶段 2：验证全量设备兼容性，服务端切换至通向 R2 的链
阶段 3：按授权策略移除不再需要的 R1
```

预置 R2 的前提是该根来源可信、设备支持其算法，并且服务端实际能取得通向 R2 的有效链。不要无目的地扩大根信任范围。

对于完全受控、只连接自有服务的设备，也可评估私有 CA，自主规划根和服务器签发。私有 CA 不天然被公共客户端信任，并引入 CA 私钥保护、轮换、吊销及运维责任；部署兼容性需确认。

## 10. TLS 失败后的备用 HTTP 恢复

### 10.1 错误识别的边界

TLS 本地验证错误可触发诊断，但不能仅凭告警准确判断根失效：

| 错误 | 可能原因 |
| --- | --- |
| 过期或尚未生效 | 服务器/中间证书时间问题、设备时钟错误，或实现检查根时间 |
| 找不到可信签发者 | 缺失中间链、根不匹配、服务端配置错误 |
| 域名不匹配 | 配置错误或连接到了冒充服务 |
| 签名或算法错误 | 内容损坏、篡改、算法不兼容 |

记录 TLS 库错误、失败证书层级（若提供）、设备时间和信任库版本。先检查时间、链和域名，进行有限重试，不自动降低验证要求。

### 10.2 HTTP 只传输已签名更新材料

设备出厂预置独立更新验签公钥。该公钥用于验证由平台授权签发的信任库更新，不依赖已失效的 TLS 根。对应签名私钥由平台在受控环境保管，避免与在线 TLS 私钥共用。

```text
TLS 验证失败
    -> 诊断时间和验证错误，有限重试
    -> HTTP 下载签名更新包
    -> 独立验签公钥验证包真实性与完整性
    -> 检查适用范围、版本和防回滚条件
    -> 原子写入候选信任库
    -> 使用候选库重新连接正式 TLS 并完整验证
    -> 成功后提交更新
```

未经签名验证不能安装新根。攻击者可以主动阻断 TLS，迫使设备进入恢复流程，所以“TLS 失败”本身不是安装新根的授权。

### 10.3 签名范围与安全条件

签名应覆盖更新版本、适用产品/设备范围、证书内容或哈希、增加/删除操作和相关策略。采用成熟的签名封装和验证实现，不自行拼接字符串设计签名协议。

- 在受保护存储保存已接受版本，拒绝回滚。HTTP 同时下载证书和普通哈希不能证明真实性。
- 初次使用或版本未提升时，旧的合法签名包仍可能被重放；如需证明最新状态，应增加独立签名的挑战响应或可信新鲜度机制。
- 限制下载体积、解析复杂度、超时和重试频率。
- 使用双副本、原子提交或事务，避免断电破坏信任库。
- 保留授权策略允许的恢复材料；不无条件恢复已明确撤销的不安全根。
- HTTP 不发送设备密码、Token、私钥或业务数据。
- 网络攻击者仍能阻断更新。签名保护真实性和完整性，不能保证网络可用。

独立验签公钥也需要长期规划：预留备用或恢复密钥，规定授权轮换和防回滚方式。公钥不保密，但未经授权的替换必须被阻止。

正常 TLS 尚可用时优先提前分发根更新。备用 HTTP 是恢复机制，不能变成关闭 TLS 验证或改用明文业务通信的理由。

## 11. 检查命令与上线验证

以下命令用于测试环境，文件名和域名需替换为实际值。

查看根信息：

```bash
openssl x509 -in root-ca.pem \
  -noout -subject -issuer -dates -fingerprint -sha256
```

离线验证服务器证书、用途、域名和链：

```bash
openssl verify \
  -CAfile root-ca.pem \
  -untrusted intermediates.pem \
  -purpose sslserver \
  -verify_hostname mqtt.example.com \
  server.crt
```

验证 ELB 实际入口：

```bash
openssl s_client \
  -connect mqtt.example.com:8883 \
  -servername mqtt.example.com \
  -CAfile root-ca.pem \
  -verify_hostname mqtt.example.com \
  -verify_return_error \
  -showcerts
```

正常结果应验证成功，例如 `Verify return code: 0 (ok)`。OpenSSL 测试不能替代设备测试，也不代表已完成吊销检查或 MQTT 业务认证。

上线前验证：

- 真实设备可握手、登录、发布和订阅，且网络访问规则正确。
- 错误域名、不可信签发者、过期证书被拒绝。
- 服务器续期以及中间链切换不会破坏设备兼容性。
- 根迁移方案在不同固件、TLS 库、设备时间状态下可用。
- HTTP 恢复拒绝伪造、篡改、错误适用范围及旧版本更新。
- 更新断电、网络中断和恢复失败不会破坏有效信任材料。
- 实际对外证书到期告警及续签部署流程生效。

## 12. 常见误区

| 误区 | 正确理解 |
| --- | --- |
| 申请证书就是获取一个新的根 | 通常申请的是服务器证书，根属于已有 CA 体系 |
| 生成私钥和 CSR 就是自签 | 自签与公共 CA 签发的区别在最终证书由谁签署 |
| 中间链是一张包含全部公钥的证书 | 多张独立证书可以封装在同一文件中 |
| 设备每次都要访问 CA 下载中间证书 | 完整链通常由 ELB 在握手中直接发送 |
| 自动续费就会更新 ELB | 续费、续签和部署是不同步骤 |
| 同一个 CA 品牌下的任意根都可用 | 必须能验证实际服务器证书的签发路径 |
| 根剩余 10 年就保证 10 年不用维护 | 有效期不等于持续签发、算法或安全承诺 |
| TLS 失败就能确认根已失效 | 也可能是时间、域名、中间链或服务端问题 |
| HTTP 下载到新根即可安装 | 必须独立验签并检查授权、版本和适用范围 |
| 单向认证只有上行加密 | 上下行都加密，单向描述证书认证方向 |

## 13. 推荐实施方案

1. 使用稳定业务域名，确认华为云 ELB 是否承担实际协议的 TLS 终止。
2. 选择公共 CA 产品与已验证的长生命周期签发路径，取得明确根信息和后续链变更政策。
3. 部署服务器证书、匹配私钥及完整中间链，配置设备严格验证。
4. 使用设备级业务凭据和权限控制，维持合理 MQTT 长连接。
5. 将续签、部署、对外验证和到期告警纳入运维闭环。
6. 设备预留多根存储和独立签名信任库更新能力，提前迁移，备用 HTTP 用于恢复。
