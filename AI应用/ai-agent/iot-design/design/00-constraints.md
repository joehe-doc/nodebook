# 设计约束清单 v1

> ⚠️ **本文件为「流程验证用虚构约束」**，用于演练 `design-doc-playbook.md` 的 Phase 0~3。
> 内容自洽但不代表任何真实系统。实际使用时，本页每个字段都必须由业务方口述确认，不得由 AI 推测填充。
>
> 项目代号：** Helios —— 分布式光伏与储能电站物联监控平台**

---

## 1. 文档类型与深度

**概要设计（HLD）**。

- 下钻到：服务拆分边界、关键中间件选型、核心链路的时序与状态迁移、非功能指标的达成机制。
- **不下钻到**：接口字段定义、数据库表结构、具体代码实现、UI 交互稿。

## 2. 读者

| 读者 | 关注点 | 对文档的要求 |
|---|---|---|
| 架构评审委员会 | 选型是否可辩驳、风险是否识别 | 每个决策要有被否掉的备选及理由 |
| 研发团队（3 个小组，共 18 人） | 服务边界、接口归属、部署形态 | 命名必须唯一且稳定 |
| 交付/售前 | 能力范围、容量承诺 | 需要能力全景图与非功能指标 |

## 3. 部署环境

- **公有云**：阿里云，单 Region（华东 1 / 杭州），**双可用区**。
- **容器平台**：ACK（阿里云 Kubernetes），节点池按「接入层 / 业务层 / 数据层」三组划分。
- **边缘侧**：每座电站 1 台边缘网关（ARM64，2C4G，Linux），客户现场部署，网络为 4G/5G 或专线，**带宽不稳定、可能中断数小时**。
- **不涉及**：私有化部署、混合云、自建 IDC（本期）。

## 4. 规模指标（全部为数字，不接受定性描述）

| 指标 | 目标值 | 备注 |
|---|---|---|
| 接入电站数 | **50 万座** | 三年目标；首年 8 万座 |
| 单站采集点位数 | 平均 **40 个** | 组串逆变器、电表、储能 PCS、环境传感器 |
| 全网点位总量 | **约 2000 万** | |
| 遥测常规上报周期 | **5 分钟**（可按站下调至 1 分钟） | 边缘网关聚合后整站一报 |
| 稳态上行消息量 | **约 1,700 msg/s** | 50 万站 ÷ 300s |
| **峰值上行消息量** | **50,000 msg/s** | 全网高频召测场景（故障后批量拉取录波数据） |
| 告警端到端时延 | **P99 < 10 秒** | 从边缘产生到用户 App 推送 |
| 遥测查询时延 | **P99 < 2 秒** | 单站 30 天历史曲线 |
| 历史数据保留 | 原始 **13 个月**；分钟级聚合 **5 年** | |
| 单站日增数据量 | 约 **11 MB** | 含录波文件 |

## 5. 可用性目标

| 链路 | 目标 | 说明 |
|---|---|---|
| 设备接入 + 告警 | **99.95%** | 单 AZ 故障不中断接入与告警 |
| 遥测查询 + 报表 | 99.9% | 可容忍分钟级降级 |
| OTA 升级 | 99% | 非实时链路，可暂停 |
| **边缘自治** | 云侧完全中断时，边缘网关须能**本地缓存 ≥ 72 小时**数据并在恢复后补传，且本地告警逻辑继续运行 | 这是硬约束，不是优化项 |

## 6. 合规与安全

- **等保三级**。
- **电力行业合规**：涉及电网侧交互的部分需满足《电力监控系统安全防护规定》——安全分区、专用网络、横向隔离、纵向认证。本平台位于管理信息大区（Ⅲ区），**不直接控制电网侧设备**，仅做监视与告警。
- **数据不出境**：全部业务数据存储于境内 Region。
- **设备身份**：一机一密 + X.509 证书双轨；证书需支持在线轮换与吊销。
- **审计**：所有下行控制指令（远程重启、参数下发、OTA）须留全量审计日志，保留 ≥ 3 年。

## 7. 技术栈约束（公司标准，不可协商）

| 项 | 约束 |
|---|---|
| 语言 / 框架 | Java 17 + Spring Boot 3.x |
| 消息队列 | **Kafka**（公司统一标准，不引入 Pulsar / RocketMQ） |
| 容器编排 | ACK（K8s） |
| 对象存储 | 阿里云 OSS |
| 关系库 | MySQL 8.0（阿里云 RDS） |
| 缓存 | Redis |
| **时序库** | **可自选**，需在 Phase 2 给出选型与理由 |
| **MQTT Broker** | **可自选**，需在 Phase 2 给出选型与理由 |
| **流处理** | **可自选**（Flink / Kafka Streams / 其他），需在 Phase 2 给出选型与理由 |

## 8. 明确不做（本期范围排除）

1. **视频 / 图像接入** —— 电站摄像头、无人机巡检图像，全部不在本期。
2. **边缘侧 AI 模型训练** —— 边缘只做规则推理，不做训练。
3. **多活容灾 / 跨 Region 容灾** —— 本期只做同 Region 双 AZ。
4. **电力交易与结算** —— 涉及电价、上网电量结算，属另一个系统。
5. **对电网侧设备的控制指令下发** —— 合规红线，只监视不控制。
6. **移动端 App 原生开发** —— 本期只提供 OpenAPI 与 H5，App 由另一团队负责。

> 以上 6 条在 Phase 1 能力脑图中须标注为「本期不交付」，**不得凭空消失**——否则后续版本无法追溯范围变更。

## 9. 既有系统与对接关系

| 系统 | 关系 | 影响 |
|---|---|---|
| **无既有平台** | 全新建设 | 不需要 Phase 1b 的 `Explore` 扫描 |
| 客户已有 SCADA / EMS | **北向对接**，本平台作为数据消费方，通过 Modbus TCP / IEC 104 从边缘网关侧读取 | 边缘网关需支持多协议解析 |
| 公司统一 IAM | 本平台的用户与权限须接入，不自建账号体系 | 影响开放 API 网关设计 |
| 公司告警中心（已有） | 告警须同时推送到该中心（Webhook） | 告警链路需保留北向输出 |
| 短信 / App 推送网关（已有） | 复用，不自建 | 告警通知的下游 |
